Operators

A PauliSentence is an operator: Pauli strings with coefficients,

\[\mathcal{S} = \sum_j c_j P_j ,\]

stored as an AbstractDict from the bit pattern of $P_j$ to $c_j$.

using SymplecticPauli

H = PauliSentence(["ZZ-", "-ZZ", "X--", "-X-", "--X"], [1.0, 1.0, 0.5, 0.5, 0.5])
PauliSentence{UInt64, Float64, 3} with 5 entries:
  0x0000000000000004 => 0.5
  0x0000000000000002 => 0.5
  0x0000000000000018 => 1.0
  0x0000000000000001 => 0.5
  0x0000000000000030 => 1.0

The keys are strings on three qubits and the values their couplings — this is the transverse-field Ising Hamiltonian at $J = 1$, $g = 0.5$. The same list of strings can come from a PauliList, from UPaulis, from index vectors or from a matrix of indices, one string per column:

PauliSentence(PauliList(["ZZ", "X-"]), [1.0, -0.5])
PauliSentence{UInt64, ComplexF64, 2} with 2 entries:
  0x000000000000000c => 1.0+0.0im
  0x0000000000000001 => -0.5-0.0im

The phase convention

This is the one thing worth reading carefully. A coefficient multiplies the bare embedding of its string — X ↦ $σ_1$, Z ↦ $σ_3$, and a Y position ↦ the real antisymmetric σ₂real rather than $σ_2$. That is what makes a product of two strings an xor and a $\pm 1$, with no $i$ anywhere.

Constructing a sentence from anything that names its strings folds in the $i^{\#Y}$ phase that turns each bare string into the Hermitian Pauli operator, so a real coefficient vector gives a Hermitian operator:

s = PauliSentence(["Y-"], [1.0])
PauliSentence{UInt64, ComplexF64, 2} with 1 entry:
  0x0000000000000005 => 0.0+1.0im
tomatrix(s) ≈ tomatrix(s)'
true

The stored coefficient is $i$, and tostring divides that phase back out, so what you read is what you entered:

tostring(s)
Dict{String, ComplexF64} with 1 entry:
  "Y-" => 1.0+0.0im

Only the raw-bits constructor takes coefficients exactly as given, without a convention:

PauliSentence(UInt[3], [1.0], 1)[UInt(3)]     # the bare Y, coefficient untouched
1.0

One consequence to keep in mind: a string with an odd number of Ys forces the coefficient type to widen, since the phase is imaginary. PauliSentence(["Y-"], [1.0]) stores ComplexF64, while PauliSentence(["YY"], [1.0]) stays Float64.

As a dictionary

Everything Base offers on a dictionary is available:

haskey(H, UPauli("ZZ-").string), H[UPauli("X--").string], get(H, UInt(0), 0.0)
(true, 0.5, 0.0)
length(filter(p -> p.second > 0.9, H))
2
sum(H.qubits - counti(k, H.qubits) for k in keys(H))   # total weight of the Hamiltonian
7

copy, empty, delete!, pop!, filter!, sizehint! and iteration over key => value pairs all behave as expected; the ones that return a container return a PauliSentence, not a Dict.

Arithmetic

Sentences add, subtract, scale, multiply and take non-negative integer powers. Types promote rather than being pinned to whatever came first:

A = PauliSentence(["X-"], [1.0])
B = PauliSentence(["Z-"], [2.0])

tostring(A + B)
Dict{String, Float64} with 2 entries:
  "X-" => 1.0
  "Z-" => 2.0
tostring(A * B)          # XZ = -iY
Dict{String, ComplexF64} with 1 entry:
  "Y-" => 0.0-2.0im
tostring(A * B - B * A)  # the commutator [X, Z] = -2iY
Dict{String, ComplexF64} with 1 entry:
  "Y-" => 0.0-4.0im

The product costs one term per pair of strings, and terms landing on the same string are summed — so a product of two sparse operators stays sparse if their strings collide, and grows if they do not. Cancelling terms are kept as explicit zeros; arithmetic does not prune, so filter! them out when the sparsity matters.

Trace

Every Pauli string but the identity is traceless, so the trace of a sentence is the identity coefficient scaled by the dimension — no matrix needed:

T = PauliSentence(["--", "ZZ"], [0.5, 1.0])
trace(T), trace(H)
(2.0, 0.0)

Dense matrices

tomatrix builds the $2^Q \times 2^Q$ matrix, and the PauliSentence constructor takes one apart again:

using LinearAlgebra

m = tomatrix(PauliSentence(["ZZ", "X-"], [1.0, -0.5]))
4×4 Matrix{ComplexF64}:
  1.0+0.0im   0.0+0.0im  -0.5+0.0im   0.0+0.0im
  0.0+0.0im  -1.0+0.0im   0.0+0.0im  -0.5+0.0im
 -0.5+0.0im   0.0+0.0im  -1.0+0.0im   0.0+0.0im
  0.0+0.0im  -0.5+0.0im   0.0+0.0im   1.0+0.0im
tostring(PauliSentence(m))
Dict{String, ComplexF64} with 2 entries:
  "X-" => -0.5-0.0im
  "ZZ" => 1.0+0.0im

Both directions are exponential in the number of qubits. They are there to check small cases against — an identity that holds for every string on three qubits is usually an identity — not to compute with.
